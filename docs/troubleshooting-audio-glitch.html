音频变调 / 周期性卡顿 排查指南

WDM2VST Ultra · 适用于"CPU 占用不高，但音频出现变调、忽快忽慢、周期性爆音"的情况
一句话结论
绝大多数"变调"不是插件算错了，而是给音频缓冲区喂数据的节奏被系统里某个驱动打断了（最常见是网卡、Wi-Fi、显卡、USB 驱动在高负载时产生的 DPC/ISR 延迟）。缓冲区一旦见底，插件的时钟恢复（PLL）就会临时调慢/调快读取速度来补偿，听感上就是变调。本指南教你定位是哪个驱动、以及如何缓解。

一、先理解现象：为什么"CPU 很低却变调"

音频是硬实时任务：每隔几毫秒就必须有一批新样本送到。WDM2VST Ultra 通过共享内存环形缓冲区在内核驱动和插件之间传音频。

  • 正常时：缓冲区里始终留有一定"余量"（目标延迟），即使偶尔抖动也不会见底。
  • 异常时：系统里某个驱动在内核态长时间占用 CPU（一次 DPC 或 ISR 执行了几毫秒），把音频驱动的写入/读取节奏挤掉了。这段时间 CPU 总占用率可以很低（只是某一核在内核态被独占），但音频缓冲区已经饿了。
  • 缓冲见底 → PLL 降速读取 / Hermite 重采样介入补偿 → 音调变低或忽高忽低；更严重时直接静音淡出再重新缓冲（爆音/断续）。

关键指标叫 DPC/ISR 延迟（Deferred Procedure Call / Interrupt Service Routine 执行时间）。它和 CPU 占用率是两回事——这就是"CPU 不高却卡"的原因。

LatencyMon 是专门测"系统是否适合实时音频"的工具，会直接告诉你哪个内核驱动的 DPC/ISR 延迟过高。

测试步骤

  1. 先把你平时会一起运行的软件全部打开（DAW、直播软件、浏览器、会议软件等）—— 要在"会触发问题的真实环境"下测。
  2. 打开 LatencyMon，点左上角绿色 ▶ Start 开始监测。
  3. 让它跑 至少 5–10 分钟，期间主动复现问题：比如做大量网络传输、切换网页、开关 Wi-Fi、运行你平时导致变调的操作。
  4. 复现到变调后，点 ■ Stop。
  5. 看结果（见下方"怎么读报告"）。

怎么读报告

Main 标签页顶部会给一句结论。判定标准（官方）：

DPC / ISR 最高执行时间含义
< 500 µs很好 系统适合实时音频
500 – 2000 µs临界，偶发问题可能来自这里
> 2000 µs有问题 几乎必然导致爆音/变调

切到 Drivers 标签页，按 DPC count 或 Highest execution (ms) 排序，排在最前面的那个 .sys 就是元凶。常见嫌疑：

驱动文件对应硬件

如果元凶是网卡 / Wi-Fi（你这次的情况）
"大量网络 IO 时变调"几乎可以确定是网卡驱动的 DPC 在高吞吐时变长。这是 Windows 实时调度下的常见现象，不是插件 bug，但下面的方法能显著缓解。

三、缓解方案（从简单到进阶）

① 提高 WDM2VST Ultra 的延迟模式 最快见效

插件里有 Latency 模式（Safe / Fast / Extreme / Insane）。更高的延迟 = 更深的缓冲区 = 能吸收更大的 DPC 抖动而不见底。

如果你在用 Fast/Extreme/Insane 又遇到网络 IO 变调，切回 Safe。代价是延迟变高几毫秒，但能换来稳定。

原理：缓冲区越深，越能"扛过"网卡驱动那几毫秒的独占而不饿肚子。

② 针对网卡的优化

  • 关闭网卡节能：设备管理器 → 网络适配器 → 你的网卡 → 属性 → 电源管理 → 取消勾选"允许计算机关闭此设备以节约电源"。
  • 关闭中断节流 / 节能模式：网卡属性 → 高级 → 找到 Interrupt Moderation、Energy Efficient Ethernet、Green Ethernet 等，尝试禁用。
  • 更新网卡驱动到厂商官网最新版（不是 Windows Update 的通用版）。老的/通用网卡驱动 DPC 表现往往更差。
  • Wi-Fi 改有线：Wi-Fi 驱动的 DPC 延迟普遍高于有线网卡，条件允许时用网线。

③ 系统级电源 / 调度优化

  • 电源计划设为"高性能"或"卓越性能"：控制面板 → 电源选项。节能计划会让 CPU 降频，加剧 DPC 延迟。
  • 关闭 CPU 核心 Parking / 动态降频（进阶，谨慎）。
  • 关闭不必要的后台程序：尤其是会大量联网的（云盘同步、P2P 下载、游戏平台后台更新）。

④ 进阶：用 Windows Performance Analyzer 精确定位 专业

如果 LatencyMon 还不够，可以用微软官方的 Windows Performance Toolkit（WPT） 抓 DPC/ISR 的精确调用栈。

WPT 官方文档（含下载）

WPT 随 Windows ADK 一起分发。用 xperf / WPR 抓 trace，在 WPA 里看 "DPC/ISR Duration"。这是专业级工具，普通用户用 LatencyMon 已足够。

四、判断"是不是 WDM2VST Ultra 的问题"

做一个对照实验，区分"系统 DPC 问题"和"插件问题"：

  1. 在 DAW 里挂一个普通的录音 / 监听通道（不经过 WDM2VST Ultra），用同样的网络 IO 复现。
  2. 如果普通通道也爆音/卡顿 → 是系统 DPC 延迟问题，按上面的方法优化系统。
  3. 如果只有 WDM2VST Ultra 通道变调、普通通道正常 → 把 LatencyMon 报告和你的 Latency 模式设置发给我们，我们继续跟进。
总结
"CPU 低却变调"的本质是 DPC/ISR 延迟而非算力不足。先用 LatencyMon 找出延迟最高的驱动（网络 IO 场景多半是网卡），然后：提高 Latency 模式 + 优化网卡设置 + 高性能电源计划，绝大多数情况能解决。这部分和 Windows 的实时调度抢占机制有关，并非插件计算错误。
